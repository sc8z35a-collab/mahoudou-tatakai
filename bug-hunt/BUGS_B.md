## 剣士 (knight.js)
- **B-012 [C][静的] 疑似影(円盤)が castShadow=true で、それ自体が影を落とす**: `mesh()` の既定で、透明な MeshBasicMaterial の円盤が不透明なシャドウマップに書き込まれる。死亡時に体が倒れても、影は足元に残る。 (knight.js:252)
- **B-013 [C][静的] 最初の1振りだけ斬撃軌跡の不透明度が違う**: 初期値 opacity=.5 を、slashEffect が命中判定時(progress>.48)に .23／.19 へ上書きし、戻さない。1振り目の前半とそれ以降で軌跡の明るさが変わる。 (knight.js:255 / game.js:216)
- **B-014 [C][静的] 最初の攻撃で2番目の斬撃(返し斬り)が出る**: `attack()` が `combo=(combo+1)%2` を先に実行するため、リセット後の1撃目は CUTS[1] になる。README の「斜め斬り→返し斬り」の順序と逆。 (game.js:291 / knight.js:282)
- **B-015 [C][静的] sRGB 指定のテクスチャをバンプマップにも使っている**: `mail`(color=true)を chain の bumpMap に、`marble`(SRGB)を床の bumpMap に使用。凹凸の強さが非線形に歪む。 (knight.js:45,71 / castle-detail.js:30)

## Node実測 (bug-hunt/tools/b/*.mjs — three@0.164.1 + DOMスタブで実ソースをそのまま実行)
- **B-016 [A][実測] (担当外 field.js) 経路探索に失敗するたびに約500msメインスレッドが止まる**: `findPath` は経路が見つからないと、各辺で `clearWalk` を呼びながら最大12000ノードまで探索する。t5.mjs の結果では、プレイヤーが実際に移動できる10568地点のうち209地点で失敗し、1回あたり約490〜580msかかった。`steer` は0.65秒ごと(またはプレイヤーが1.5以上動くたび)に再探索し、`stepBattle` のサブステップ内でも呼ばれる。そのため、プレイヤーがその位置に立つだけで0.5秒前後のフリーズが繰り返される。成功した経路でも1218地点で50msを超えた(最大612ms)。
- **B-017 [A][実測] (担当外 field.js) プレイヤーは入れるが NPC は経路を引けない場所があり、NPC が棒立ちになる**: 例 (11.0,13.1)（柱の台座と壁の間の側廊）、(-10.68,-3.33)（机・壺・壁の間）、(-10.8,-9.1)、(-5.4,-27)（壇上の石像付近）、入口の角 (-11.5,16.68)。原因は次の2つ。(1) グリッドの間隔が0.45と粗い。(2) グリッド側の半径が0.345で、プレイヤーの0.32より大きい。さらに斜め移動には直交方向の両隣が空いていることが必要で、1マス幅の通路が孤立する。経路が空だと `steer` はゼロベクトルを返し、NPC は動かない（視線が通らなければ攻撃もしない）。プレイヤーは安全地帯に入って戦闘を無期限に止められる。
- **B-018 [B][実測] (担当外 field.js) NPC 用グリッドが部屋の北端・東端・入口側を覆っていない**: グリッド範囲は x -11.55〜11.40、z -30.05〜16.30。プレイヤーの移動範囲は x ±11.68、z -30.18〜16.68 なので、東側0.28、入口側0.38の帯にグリッドのセルがない。`nx=52,nz=104` を固定値にしたための計算漏れ。
- **B-019 [B][実測] 入口扉枠の石柱(±3.65)にプレイヤーが0.35めり込む**: B-006 を実測で確認。(3.65,0,10) から +z へ進むと z=16.680 まで入れる。柱の前面は z=16.65 なので、体の中心が柱の前面より内側に入る。

## テスト (tests/*.js)
- **B-034 [B][実測] README の「113/113合格」は、実際には検出力のないテストを含む**: jsdom で `?selftest=1` を実行して113/113を再現したうえで、各テストが何を検証しているかを調べた。
  - smoke「Neutral dodge moves away from the enemy」は、`player.z` が増えることだけを見ている。配置が逆(player -1 / enemy +1)だと実際の移動は -0.9 になるので、「+zへ動くこと」しか検証していない。
  - smoke「Actual castle walls constrain movement」は、(100,-100) を投影して x≤max と z≥min の2辺しか確認していない。
  - 「NPC approaches the player」は `updateAI(.1)` の1回で z が増えるかだけを見ている。経路に失敗したときの停止(B-017)は検出できない。
  - field「NPC can route to throne platform」は経路長>0しか見ていない。探索時間(B-016)は計測していない。
- **B-035 [B][実測] selftest の途中に、実際には押されない入力経路がある**: smoke は `$('start-button').click()` と `dispatchEvent(new PointerEvent('pointerdown'))` を使う。pointerId を指定しないので、既定値(1)が常に使われる。setPointerCapture を伴う防御ボタン(guardPointers)は、直接 `add(11)` で操作していて、ボタンの pointerdown 経路は一度も通らない。複数指の実装(README で強調)を検証していない。
- **B-036 [C][実測] selftest の実行後、ゲームが `paused=true` のまま戦闘状態で残り、PAUSE ダイアログも出ない**: `readyScreenshot()` は paused を直接 true にし、ダイアログを開かない。この間、Escape・J・Space はすべて無視される（keydown が paused で return するため）。画面上は戦闘HUDが出ているのに、一切操作できない。タブを切り替える・フォーカスを外すと PAUSE ダイアログが初めて出て、「戦いに戻る」を押すと、確認用に固定した HP83/106・経過21秒のまま、実際の戦闘が再開する（t_b3.mjs で paused=true・pauseOpen=true を確認）。
- **B-037 [C][静的] テスト用に `data-selftest` 属性でも起動できる経路が残っている**: README には「テスト用HTML属性を除去」とあるが、game.js:461 の `document.body.hasAttribute('data-selftest')` と `document.body.dataset.reviewArea/reviewPose` は残っている。

## 音声 (担当外 game.js — Aの A-0xx に音声関連の記載がないのを確認済み)
- **B-060 [B][静的] 風切り音・被弾音・防御音・回避音を鳴らすたびに、ノイズバッファーを JS で新しく生成する**: `sfx()` は毎回 `audio.createBuffer(1,sampleRate*length)` を作り、`Math.random()` で埋める。48kHz なら1回に約8,600サンプル。命中1回で swing+hit の2回、防御なら2回生成して GC を増やす。1つのバッファーを使い回せば足りる。
- **B-061 [C][静的] サウンドON時に `resume()` の完了を待たずにフェードを予約する**: `setSound(true)` は `audio?.resume()` の Promise を待たずに `ambientGain.gain.setTargetAtTime(...,audio.currentTime,.3)` を呼ぶ。suspended 中は currentTime が0で止まっている。iOS Safari で最初のタップ時に resume が非同期で遅れると、アンビエンスのフェードの開始時刻がずれる。
- **B-062 [B][静的] ページを隠してから戻ると、サウンドがONでもアンビエンスが無音のまま戻らない場合がある**: `syncPause()` は `document.hidden` が false に戻ると gain を .65 に戻すが、iOS/Safari はバックグラウンドで AudioContext を `interrupted`/`suspended` にする。`visibilitychange` で `audio.resume()` を呼ぶ処理がないので、復帰後に効果音もアンビエンスも鳴らなくなる可能性がある。※実機Safariでは未検証（コード上、復帰時に resume する経路がないことは確認済み）。
- **B-063 [C][静的] 一時停止・設定ダイアログ中もアンビエンスが鳴り続ける一方、タイトル画面でも常時鳴る**: `syncPause` の gain 条件は `soundEnabled&&!document.hidden&&!contextLost` だけで、`paused` を見ていない。ダイアログでの一時停止中も戦闘BGMの低音が鳴る。（仕様の範囲とも取れるので軽微）
- **B-064 [C][静的] 勝利音はあるが敗北音がない**: `finish(win)` は `if(win)sfx('win')` だけで、敗北時は無音になる。`sfx` にも敗北用の分岐がない。
- **B-065 [C][静的] NPC の攻撃は命中判定の瞬間(progress .48)に初めて風切り音が鳴り、予備動作の音の合図がない**: プレイヤーの攻撃は `attack()` の開始時に swing を鳴らすが、敵は `if(f.enemy)sfx('swing')` を命中判定の時点で鳴らす。風切り音とほぼ同時に命中音が重なり、音で予備動作に反応する手段がない。
